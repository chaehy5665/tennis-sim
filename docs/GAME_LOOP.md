# 게임 루프 설계 (초안, 2026-09-24)

상태: **DRAFT**. D1~D4는 확정(아래 "확정된 결정"). 각 항목의 Core 지원 현황은 HEAD `9d0d581` 코드 기준이다.

## 한 줄 정의

플레이어는 테니스 선수를 **직접 조작하지 않는다**. 코치로서 선수의 능력을 읽고, 상대를 분석해 전술을 짜고,
경기 흐름에 맞춰 지시를 바꾸고, 결과를 보고 다음 준비를 한다. 경기 결과는 항상 Core 시뮬레이션이 결정한다.

플레이어가 느껴야 할 것: **"내 판단 때문에 이겼다(졌다)"**. 운이나 숫자 차이만으로 결과가 나는 것처럼 느껴지면
이 장르는 실패한다.

## 세 겹의 루프

```text
매크로 (시즌, 수 주~수 개월)
  대회 선택 → 훈련/휴식 배분 → 성장·랭킹·재정 → 다음 대회
    │
    └─ 미드 (경기 1개, 10~30분 실제 시간)
         상대 분석 → 경기 전 전술 → 경기 관전 → 경기 후 리뷰
           │
           └─ 마이크로 (체인지오버, 약 2게임마다)
                흐름 확인 → 지시 변경 → 효과 관찰
```

### 마이크로 루프: 체인지오버 지시

| 요소 | 내용 | Core 지원 |
|---|---|---|
| 결정 시점 | 홀수 게임 뒤 코트 체인지 때 (실제 테니스 리듬과 일치, 결정 간격 약 2게임) | ✅ `MatchEngine.AdvanceToChangeover()`가 엔드 교대 직후 멈춤. `QueueTactics`로 준 지시는 다음 포인트부터 적용되고 replay에 기록됨 |
| 결정 내용 | 공격 대상(균형/백핸드 공략), 공격성(안전/균형/공격), 서브 방향(혼합/와이드/바디/T) | ✅ `Tactic` |
| 결정 근거 | 직전 구간 통계: 첫 서브 성공률, 상대 백핸드 에러, 랠리 길이, 체력 | ✅ `SegmentStats.Compute(record, from, to)`: 득점, 서브 득점, 첫 서브, 더블 폴트, 위너, 포핸드/백핸드 에러와 타수, 평균 랠리, 구간 끝 체력 |
| 상대의 대응 | 상대 코치도 체인지오버마다 전술을 바꿈 | ✅ `OpponentCoach.Decide`: 사람 코치와 같은 정보(프로필, 양쪽 현재 전술, 구간·누적 통계)만 사용, 난수 미사용, 지시는 replay에 기록 |
| 피드백 | 지시 후 몇 포인트 안에 선택 샷 분포와 결과가 달라지는 것이 보여야 함 | ◐ `Choices`, `CandidateRejections` 기록은 있음. 표시 UI 없음 |

**위험 (측정됨)**: [BALANCE_DIAGNOSIS.md](BALANCE_DIAGNOSIS.md)에 따르면 현재 전술 공간은 "백핸드 공략 + Wide 서브,
Safe 금지"로 풀려 있고 카운터 구조가 없다. 정답이 하나로 굳어 있으면 마이크로 루프는 의미를 잃는다. 전술은
**상대에 따라 정답이 달라지는 구조**(가위바위보 관계)여야 한다.

### 미드 루프: 경기 한 개

| 단계 | 플레이어 행동 | 보여줄 정보 | Core 지원 |
|---|---|---|---|
| 1. 상대 분석 | 스카우팅 리포트 읽기 | 상대 강·약점, 최근 경기 샷 분포 | ◐ 능력치는 `PlayerProfile`에 있음. 과거 경기 기록 누적은 없음 |
| 2. 경기 전 전술 | 초기 전술 선택, 선택적으로 조건부 계획 | 예상 매치업 | ✅ 초기 `Tactics` |
| 3. 관전 | 3D 중계 또는 2D 탑뷰, 배속/하이라이트 | 점수, 실시간 통계 | ◐ 리플레이 있음. 한 세트가 시뮬레이션 시간 약 610초(10분)이므로 **배속과 하이라이트 필수** |
| 4. 리뷰 | 무엇이 먹혔는지 확인 | 목표 대비 착지점 히트맵, 전술별 득점 | ✅ `IntendedTargets`, `FirstLandings` |

**경기 형식**: Core는 현재 한 세트만 지원한다. 3세트 경기를 전부 보면 30분 이상 걸리므로, 기본 관전 모드는
"중요 포인트 하이라이트 + 체인지오버 정지"로 두고 전체 관전은 선택으로 한다.

### 매크로 루프: 시즌

| 요소 | 내용 | Core 지원 |
|---|---|---|
| 대회 일정 | 대회 등급, 코트 표면, 상금, 랭킹 포인트 | ❌ (표면은 바운스 모델 V1에 개념만 있고 캘리브레이션 안 됨) |
| 훈련 | 능력치별 성장, 기간과 비용 | ❌ `PlayerProfile`은 고정값 |
| 체력/부상 | 연속 출전 피로, 휴식 | ◐ 경기 내 `stamina`만 있음. 경기 간 누적 없음 |
| 성장 곡선 | 나이, 잠재력 | ❌ |
| 재정 | 상금, 코치 비용, 스폰서 | ❌ (Core 밖 게임 계층) |

매크로 루프 대부분은 **Core 바깥의 게임 계층**이다. Core는 "주어진 두 선수와 전술로 경기 한 개"만 책임지고,
시즌 상태는 별도 모듈이 소유한다. 이 경계를 지켜야 Core의 결정론과 테스트가 유지된다.

## 설계 원칙

1. **결과는 Core만 결정한다.** UI, 애니메이션, 하이라이트 선택은 결과를 읽기만 한다.
2. **모든 결정에는 근거 정보가 있어야 한다.** 볼 수 없는 수치로 결정하게 하지 않는다.
3. **지시의 효과는 관찰 가능해야 한다.** 지시 후 몇 포인트 안에 샷 선택 변화가 보여야 한다.
4. **정답 전술이 고정되면 안 된다.** 상대 유형별로 최선의 전술이 달라야 한다.
5. **짧은 세션을 허용한다.** 경기 하나를 10분 안에 끝낼 수 있어야 한다.

## 확정된 결정 (2026-09-24)

| # | 질문 | 결정 | 비고 |
|---|---|---|---|
| D1 | 누구를 관리하나 | **선수 1명의 전담 코치** | 아카데미(여러 명)는 보류. 매크로 결정은 한 선수의 일정·훈련·휴식 배분으로 만든다 |
| D2 | 경기 중 개입 빈도 | **체인지오버마다** | 실제 테니스 리듬과 맞고 결정 밀도가 적당함 |
| D3 | 관전 표현 | **2D 탑뷰 먼저**, 3D는 이후 | 게임성 검증 비용이 가장 낮음 |
| D4 | 경기 형식 | **초기 1세트**, 이후 3세트 | |

D1 때문에 선수 여러 명 사이의 자원 배분이 없다. 따라서 매크로 루프의 긴장은 **한 선수의 체력·부상 위험과
대회 출전 욕심 사이의 균형**, 그리고 **어떤 능력치를 키울지**에서 나와야 한다. 매 경기 상대가 바뀌므로
미드 루프의 상대 분석과 전술 선택 비중이 더 커진다.

## 최소 플레이 가능 버전 (수직 슬라이스)

목표: "상대를 보고 전술을 고르고, 체인지오버에 바꾸고, 결과를 리뷰한다"를 **한 경기**로 체험할 수 있게 한다.
시즌, 훈련, 재정은 포함하지 않는다.

필요한 작업:

1. ✅ **Core**: 체인지오버 시점에서 경기를 멈추고 지시를 받는 진행 API (`AdvanceToChangeover`). 지시는 사전 입력
   `Instructions`와 같은 기록으로 남아 리플레이가 정확히 재시뮬레이션된다.
2. ✅ **Core**: 구간별 통계 집계 (`SegmentStats`).
3. ✅ **밸런스**: 1차 진단과 engine v4 조정 완료 ([BALANCE_DIAGNOSIS.md](BALANCE_DIAGNOSIS.md)). 남은 문제는 그 문서의
   "아직 풀리지 않은 것".
4. ◐ **UI**: 경기 전, 경기 관전(2D 탑뷰), 체인지오버, 리뷰 화면을 Unity UI Toolkit으로 구현했다. 소스 구현이며
   Unity 컴파일과 화면 확인은 아직이다([UNITY_COACH_UI.md](UNITY_COACH_UI.md)).
5. ◐ **관전**: 코치 UI 안의 2D 탑뷰로 대체했다. 배속(1×/4×/16×), 일시정지, 다음 체인지오버까지 건너뛰기를 지원한다.

슬라이스를 플레이해 보고 **체인지오버 결정이 재미있는지** 판단한 뒤에 매크로 루프와 3D 연출에 투자한다.

UI 전에 판단할 수 있도록 텍스트 프로토타입이 있다. 상대(B)는 기본적으로 `OpponentCoach`가 코칭하고,
`--opponent fixed`면 초기 전술을 유지한다. UI 와이어프레임: https://claude.ai/artifact/GshzaRGoUCtLYDMyZMayU6 (비공개).

```bash
dotnet run --project src/TennisSim.Cli --no-build -- coach --seed 42 --player-b defender --out artifacts/coached.json
```
